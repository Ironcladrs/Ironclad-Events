# Owner’s in-game acceptance test

Automated tests do not prove RuneLite widget timing, real loot ordering or game chat variants. The repository’s AGENTS.md forbids agents from testing in game. These steps are for the owner, using a test event and their own account. No Hub submission until the relevant checks pass on the tested commit.

Start with `./gradlew run` on Java 11. Use [RuneLite’s Jagex-account instructions](https://github.com/runelite/runelite/wiki/Using-Jagex-Accounts) if needed. Bot/web changes must first be deployed deliberately, with the required server features enabled for the test; this implementation does not deploy them automatically.

1. With fresh settings, log in. Setup lists all thirteen upload switches off; no network request occurs with Connect off. Hide and restore the side panel.
2. Enable Connect, read the warning, paste a new website key. Check linked status. Try a revoked key and a key belonging to a Discord owner without this RSN linked: the panel must explain each problem.
3. Enter a live test event. Check team, standings, revealed tasks, captain priority, recommendations and links. Multiple events must switch correctly. Compare a fogged event with the site: unopened doors, floors, rival plans and secret events must remain hidden.
4. Enable automatic drops and screenshots. Receive a matching drop: one claim, one queue card and the screenshot on My Status. Run Dink too; the same drop must remain one claim. Test the reverse arrival order and a later screenshot if possible. Check item stacking, raid/chest/casket loot and KC.
5. Approve and deny claims as staff. Check one appropriate chat notice and desktop notification within the polling interval, with a denial reason. Disable the respective notice switches and repeat.
6. Before the trial event starts, add an item-linked numeric field to its precheck and select Plugin precheck evidence → Enable bank check with the expected count. A name/instruction alone remains a picture check. Bank rules cannot be changed once the event starts. Enable bank prechecks. Open the bank: only asked counts appear. Check noted items/placeholders, inventory and equipped copies. **Not now** sends nothing. **Send** files the displayed values. Matching expected counts approve; a mismatch stays pending. Automatic-for-this-event starts unchecked and stops at logout/account/consent changes. Delete your bank answers on the site: the precheck becomes owed again.
7. For a picture precheck, open the right game interface, Take screenshot, inspect the thumbnail and chat, optionally enter a value, then Send. Capture alone must never upload. Discard works. Check the site’s review queue. Collection-evidence types should file from a fresh account snapshot for staff review.
8. Enable live progress and train an event-tracked skill/kill a tracked boss. See provisional progress. Log out to the lobby to update hiscores; the ordinary WOM refresh must confirm it. Scores must always remain WOM-only. Non-tracked metrics must never appear in requests. Check activity minutes in the own-team view.
9. Enable account sync. Open your own collection log: compare quantities/totals and profile highlights. Obtain a new slot with game notifications on. Opening someone else’s POH log must not replace yours.
10. Compare CA tier totals, completed task IDs, account type, levels, quest and diary eligibility with the game. Complete a combat task and check the next snapshot.
11. Enable PBs. Set a new PB at a ladder boss. Staff see time, party size, worn gear, combat levels and optional screenshot. It stays unranked until approved. Verify solo/duo/raid variants; an ordinary completion and an old “Personal best:” value must not create a new PB. Check the no-picture label and unknown-boss personal record.
12. Enable clan chat on two members: each typed Ironclad message appears once in the staff channel. Test guest/friends/public/private chat and system broadcasts: none must relay. Discord mentions must stay disabled. Verify sender/title sanitization and a pause in coverage.
13. Simulate an unavailable site: uploads retry with the same request UUID, stop after 15 minutes and never persist to disk. Restore the connection. Try capture while no frames arrive: it must return without hanging. Manual sync must honor its throttle.
14. Turn Connect off during queued work: no further upload, queue cleared, coverage session closed best effort. Log out, change account, switch to a non-standard profile, disable and re-enable the plugin. No stale callback, screenshot, bank consent or prior-account payload may cross into the new session.
15. On the website, create/revoke keys, export data and erase a disposable member. Check staff evidence access is audited. Run event teardown against a disposable finished event: bank details, their field values and provisional/activity records disappear while the precheck decision remains.

Record RuneLite version, plugin commit, server/web commits, test event, each outcome and any chat lines needing parser fixtures. Never include bearer keys or unrelated private chat in a bug report.

16. With automatic drops off, enable **Share my own deaths**. Verify only your own death is announced once with Dink also running, in either arrival order. Keep **Death screenshots** off first: no picture must leave. Enable it separately and verify the picture goes to the configured clan channel. Test rapid separate deaths and death variants you use (ordinary, safe activities, raids); no wealth, location or killer names may appear in the plugin request. NPC/other-player deaths must do nothing.
17. Independently enable pets, milestones and clue completions. An existing 99 at login must not announce; a real new 99/total milestone should. Complete a clue: verify tier/total and self-reported weekly history. A pet notification should announce once with Dink also on. Other players’ clan broadcasts must never create your activity. Delete the activity history and verify it disappears without changing event scores or collection snapshots.
18. Compare detailed task progress and next steps in each event type you run, including held Domination territories, captured Race targets, Tug ropes, current Connect 4 fronts, a fogged maze, current track turns and Paths branches. A completed/repeating/not-current task must be described accurately; unrevealed objectives remain absent.

19. Future-event compatibility: use a staff-created, rostered trial event sent with `view.mode=generic`, then with an unsupported view version. Both should show its name, schedule and Open event link plus the reporting-paused explanation. Neither should show tasks/captain/precheck controls or report event progress. A normal v1 event beside it must still work. Verify a newly named event using the standard v1 fields displays its tasks without a client update. These fixtures belong on the isolated test server; do not edit live payloads. Independent big-drop/personal opt-ins may still operate.

20. Settings groups: open Ironclad Events in RuneLite Configuration. Confirm all nine sections expand/collapse, your existing toggles/key survived, and all new installs still have uploads off. Set personal loot filters, preview clan settings in the panel, and enable Use clan settings. No upload toggle should change. Staff change a clan filter in Leadership settings; it should appear on the next sync with a new revision. Use personal settings should restore your previous values. A new screenshot/chat recommendation must never enable that upload. Without Connect there must be no preset request.
21. Loot filters: excluded source names match exactly (case/spacing normalised), a drop made only of excluded items is skipped, and a mixed drop retains the complete list. A higher personal Wall of Fame minimum must not block a live event match. Exclusions intentionally can block event submissions, as the preview warns. Test using ordinary low-value drops in an owner-controlled trial event.

22. Scroll regression: with a long event/task list, use the sidebar mouse wheel and scrollbar to reach the bottom, including the footer Sync button. Return to the top and use the Sync now button under the logo. Resize the client shorter and repeat. Check opening Settings and uploads still permits scrolling through the entire setup view. Neither action should require horizontal scrolling.

23. Picture preview: Take screenshot, then View full size. Read details at native capture resolution, scroll vertically/horizontally if needed and close the dialog. No upload should occur until Send picture. The original small preview and Discard must still work.

24. Panel look (redesign of 2026-11-20). The sidebar button shows the Ironclad helmet and the panel header shows the full logo with "Connected" or "Not connected". In a live event: the event box shows time left and an Open event on site button; the team box shows rank and score; What to do now, Prechecks owed, Standings, Captain's plan, Tasks, My claims, Live progress and Links each fold shut with their header and stay shut after Sync now. Sections with nothing in them do not appear (Live progress and My claims always do, with a short empty note). Item pictures load beside tasks; clicking a task name opens it on the site. Claims show Approved, Waiting or Denied in words as well as colour. Hover an upload row in Settings and uploads to see exactly what it sends. No text is cut off at the right edge at the default sidebar width. Check the Plugin Hub listing icon (the full logo) once submitted.

25. Linking and settings (2026-11-20). With Connect off, the side panel's Link my account button is greyed out with the two steps. Turn Connect on (read the warning): press Link my account. Your browser opens ironcladrs.com/plugin with the same code the panel shows; approve it. Within a few seconds Plugin key fills in by itself and the panel connects. Cancel stops it; an unused code expires after ten minutes and the panel says so. Try "That's not my code" on the site, and a copied key from "Or copy a key instead" as the fallback. In RuneLite's settings, every name is readable without being cut off, sections are numbered 1 to 9, and hovering each setting says exactly what it sends. Your earlier choices and key are still set after updating.

26. One gate and clan defaults. Only Connect asks "Are you sure?"; every switch below it starts off and toggles without a prompt, and nothing sends while Connect is off. With a linked account and no uploads on, the panel shows Clan defaults with Enable clan defaults: the confirmation names each switch it will turn on and shows the IP warning; Cancel changes nothing; Enable turns on exactly that list and Use clan loot filters, and nothing else. Check the split switches: an event tile drop files with Wall of Fame drops off and does not appear on the Wall of Fame; a big non-event drop sends only with Wall of Fame drops on; PB, drop and death screenshots each follow their own switch; with only Collection log on, the site gets the log but no quests, levels or CAs. Tasks in the panel show one heading per category.
